### 3.1 R01 教案助手 TODO 规划（任务池搭建）

- 任务类型：规划 / 任务池设计
- 主要产出：围绕「大学计算机教案助手」建立了首批结构化 TODO 列表，并约定任务类型轮换（规划/研究/设计/工具），避免单一方向。
- 价值评估：
  - V1 高——明确了一条长期主线（教案助手），后续多轮任务沿用该任务池作为来源。
  - V2 高——R02、R03、R06、R16、R17 等任务都可视为对 R01 规划的具体化落实。
  - V3 高——与用户长期目标强一致，为后续扩展预留了足够空间。
- 成本与坑点：
  - C1 低——基本不依赖外部工具和环境，主要是思考与结构设计。
  - C2 低——几乎没有外部脆弱点，但需要适度控制粒度，避免一次性规划过细导致后期难以调整。
- 关键经验：
  - 建立「围绕长期目标的任务池」是非常高性价比的起步任务，宜尽早完成；
  - 规划任务应更关注方向与类型分布，而非一次性锁死所有细节。

### 3.2 R02 程序设计课样例教案（高质量样例）

- 任务类型：高质量样例 / 内容生产
- 主要产出：完成了一份围绕 C 语言分支结构的完整样例教案，涵盖教学目标、学情分析、重难点、教学流程、代码示例与练习题，深度和结构都可作为后续教案的标杆。
- 价值评估：
  - V1 高——形成了「深度样例」范本，有助于后续自动/半自动教案生成时对标质量；
  - V2 中-高——为 R03 通用模板和 R06 教案知识库设计提供了直观参考，但复用更多是“风格与深度”层面而非直接结构依赖；
  - V3 高——直接服务于大学计算机课程（程序设计）场景，与长期目标高度一致。
- 成本与坑点：
  - C1 中——需要较多领域知识与教学设计思考，但几乎不依赖外部工具；
  - C2 低——主要风险在于一次性写得过细导致后续不易泛化，不过本次样例深度对后续模板抽象反而是利好。
- 关键经验：
  - 在系统建设早期投入 1–2 个「高质量端到端样例」非常值得，可为后续抽象和自动化提供标尺；
  - 此类任务应控制在少量高质量样例，而不是铺开大量相似样例，以免分散精力。

### 3.3 R03 通用教案模板（结构化模板）

- 任务类型：模板设计 / 结构抽象
- 主要产出：面向大学计算机课程的通用教案模板，涵盖课程信息、三维目标、学情分析、重难点、教学流程、资源与作业、课程思政、反思等模块，并对编程课/系统课/理论课给出了差异化提示。
- 价值评估：
  - V1 很高——高度结构化模板，可直接作为后续教案生成、知识库落盘和自动化工具的统一格式；
  - V2 高——R06 teaching_kb 目录规划、R16 教案→PPT 映射等都以此为逻辑基础；
  - V3 高——精准服务「教案助手」主线，是长期基础设施之一。
- 成本与坑点：
  - C1 中——需要在「足够通用」和「不至于空泛」之间反复权衡，但对外部环境依赖极低；
  - C2 低——主要风险在于后期发现字段不足或冗余，需要版本演进，但初版成本可控。
- 关键经验：
  - 在明确长期方向后，尽早设计统一模板/数据结构能极大降低后续任务碎片化程度；
  - 模板任务适合基于至少一个高质量样例（如 R02）抽象，而不是凭空设计字段。

### 3.4 R04 浏览器链路修复与 GNN 检索边界（工具链探测）

- 任务类型：工具链探测 / 环境修复
- 主要产出：打通 TMWebDriver + Chrome + Tampermonkey 的浏览器自动化链路，验证了 `web_scan` / `web_execute_js` 的基本用法；同时在 Google Scholar 上试探学术检索，识别出 reCAPTCHA 等风控限制，不再依赖其做高频抓取。
- 价值评估：
  - V1 中——没有产出模板/结构，但为后续涉及浏览器操作的任务提供了可行链路和已验证脚本片段；
  - V2 高——为 R09、R11 等学术抓取相关任务提供了前置环境与边界认知；
  - V3 中——与教案助手主线关系间接，但为学术助手子线打基础。
- 成本与坑点：
  - C1 中-高——需要配置和验证多组件（浏览器、驱动、userscript），调试成本明显高于纯本地任务；
  - C2 高——强依赖外部站点与风控策略，Google Scholar 的限制使自动化抓取不稳定。
- 关键经验：
  - 针对「工具链可用性」的专门探测任务是必要的，但应以“确认边界+给出推荐站点/做法”为目标，而不是在脆弱站点上深挖；
  - 对高风控站点（如 Scholar）宜早做放弃决策，将长期抓取任务转移到更友好的源（如 arXiv/OpenReview）。

### 3.5 R05 GNN 论文追踪表结构设计（结构化表+schema）

- 任务类型：模板设计 / 数据结构抽象
- 主要产出：设计了 GNN 论文追踪表模板 `gnn_paper_tracker_template.md` 与对应 JSON schema，统一了论文 ID、元信息、标签、优先级、阅读状态、摘要与笔记等字段，为后续自动抓取与系统化管理提供了骨架。
- 价值评估：
  - V1 高——结构化追踪表是可长期复用的核心数据结构，可扩展到其他方向论文；
  - V2 高——直接支撑 R08 单文纪要模板、R09 样本标注及未来潜在的自动抓取脚本；
  - V3 中-高——服务于「学术助手/GNN 研究」子目标，与教案助手主线间接相关但仍有价值（教学科研一体场景）。
- 成本与坑点：
  - C1 中——需要思考字段的覆盖度与可扩展性，但实现过程主要是本地文件编辑，工具依赖低；
  - C2 低——风险主要在于早期字段设计不够通用，后续演进需要兼容历史数据，但可通过版本标记缓解。
- 关键经验：
  - 对于预期会有「持续积累」的内容（论文、课程、项目），优先抽象统一数据结构非常划算；
  - 结构设计任务应兼顾当前具体需求（GNN）和未来扩展空间（其他方向论文），在复杂度和通用性之间找到折中。

### 3.6 R06 教案助手知识库结构规划（teaching_kb 物理结构）

- 任务类型：信息架构设计 / 目录规划
- 主要产出：在 `./teaching_kb/` 下规划了课程与课次两级目录结构（如 `courses/<课程名>/lessons/LXX_主题/`），并给出了教案、素材、习题、PPT 等文件在物理目录中的落盘约定，附带一个「编译原理-词法分析」示例。
- 价值评估：
  - V1 高——统一的物理结构便于后续脚本遍历、检索与批量生成，是教案助手的重要基础设施；
  - V2 高——直接承接 R03 模板，并为 R16 PPT 映射、R17 命名规范等提供锚点；
  - V3 很高——与教案助手长期目标强耦合，是落地而非仅概念层面的设计。
- 成本与坑点：
  - C1 中——需要在「直观易用」与「便于自动化」之间权衡命名与层级深度，但工具依赖不高；
  - C2 中——一旦结构确定，后期大改成本较高，因此初版需尽量兼顾多种课程类型的需求。
- 关键经验：
  - 在有了模板（R03）之后，用一次专门任务把物理目录结构定下来，能显著减少后续任务的随意命名与碎片化；
  - 目录规划任务最好配至少一个真实示例目录，以检验可操作性。

### 3.7 R07 学术脚本与工具清单（环境盘点）

- 任务类型：环境盘点 / 工具清单
- 主要产出：梳理了与学术研究、教案助手、自主任务相关的本地脚本与配置，如 `skill_search` 相关索引、本地 research-paper-kb 实现、teaching_kb 相关 SOP 与早期报告等，形成一份「已有工具/脚本地图」。
- 价值评估：
  - V1 中——清单本身不是模板，但为后续发现和复用现有资产提供导航；
  - V2 中-高——为之后设计学术助手工作流和调用本地脚本提供了重要上下文；
  - V3 中——与教案助手主线间接相关，更偏向「元维护」。
- 成本与坑点：
  - C1 低-中——主要是读文件和整理信息，技术难度不高；
  - C2 低——风险主要在于清单更新不及时导致信息陈旧，但不会破坏现有流程。
- 关键经验：
  - 在系统演进到一定阶段后，专门做一次「资产盘点」任务有助于避免重复造轮子；
  - 盘点任务应聚焦于建立索引和发现缺口，而非在同一任务内尝试修补所有缺口。

### 3.8 R08 GNN 论文阅读纪要模板设计（单篇精读模板）

- 任务类型：模板设计 / 深度阅读支持
- 主要产出：设计了单篇 GNN 论文深度阅读的 Markdown 模板，包含问题背景、方法细节、实验设计、优缺点、个人收获、复现笔记、相关工作、总体评价等结构化字段，并与追踪表通过 ID/notes 形成关联思路。
- 价值评估：
  - V1 高——模板可复用于大量论文阅读，鼓励形成统一的阅读与记录习惯；
  - V2 高——与 R05 追踪表形成「宽表 + 深读」的互补结构，支撑后续构建论文知识库；
  - V3 中-高——服务学术助手子目标，与教案助手主线存在教学科研联动的间接价值。
- 成本与坑点：
  - C1 中——需要把个人阅读习惯抽象为通用结构，但主要是思考成本；
  - C2 低——模板本身风险小，后续只需根据实际使用反馈微调字段。 
- 关键经验：
  - 对「单实例深度处理」场景（如单篇论文、单个项目），设计统一纪要模板可以显著降低后续复盘与迁移成本；
  - 此类模板与追踪表类结构（R05）联合设计效果更好，可预留互相引用的锚点。

### 3.9 R09 arXiv GNN 新文手工样本标注（结构验证 + 小样本）

- 任务类型：小规模实验 / 结构验证
- 主要产出：基于 arXiv 搜索 GNN 相关论文，使用 JS+Python 抽取字段并手动整理 3 篇 2026 年 GNN 论文样本，写入 `gnn_paper_tracker_2026_samples.md`，字段与 R05 追踪表模板对齐，用于验证结构与流程的可行性。
- 价值评估：
  - V1 中-高——样本本身数量不多，但为后续自动化抓取与批量管理提供了「已验证格式」示例；
  - V2 高——直接检验了 R05 结构和 arXiv 抓取链路，为 R11 的站点策略结论提供了实证支撑；
  - V3 中——偏学术助手方向，与教案助手主线是松耦合补充。
- 成本与坑点：
  - C1 中——需要在浏览器端与本地脚本之间配合，操作步骤略繁琐，但规模刻意控制在小样本；
  - C2 中——涉及外站访问，但选择的是相对友好的 arXiv，风控与不确定性显著低于 Scholar。
- 关键经验：
  - 在设计好结构后，通过「少量高质量样本」来验证字段设计和抓取流程，是比一上来就大规模抓取更稳妥的路径；
  - 实验型任务应明确“验证什么假设”，如本任务即集中验证：R05 字段是否足够 + arXiv 页面的解析是否顺畅。

### 3.10 R10 自主任务与定时任务协同规则（调度策略）

- 任务类型：流程规则设计 / 调度策略
- 主要产出：梳理并明确了自主任务（R 系列）与定时任务之间的协同与优先级规则，包括：何时可以被定时任务中断、如何在 history 与 TODO 中记录切换、任务编号自增约定、以及在长任务中如何控制轮次与避免饥饿等原则。
- 价值评估：
  - V1 中-高——规则本身可长期复用到所有后续自主任务；
  - V2 高——直接影响任务执行的稳定性和可预期性，是后续所有 R 系列的共用基础；
  - V3 中——与教案助手目标的关系是间接的，但对整体「系统作为助手」的可用性影响明显。
- 成本与坑点：
  - C1 中——需要从已有执行记录中抽象模式并与现有 SOP 对齐，思考成本略高；
  - C2 中——若规则与现实执行不一致，可能引发混乱，需要在设计时就考虑向后兼容与渐进修正。
- 关键经验：
  - 在任务数量和类型增加后，尽早为「调度与协同」单独设立规则设计任务，可以减少后续每次 ad-hoc 决策的心智负担；
  - 这类元规则应保持简洁、可机械执行，并与 history/TODO 的结构紧密对齐，避免出现「写不进现有记录系统」的规则。

### 3.11 R11 适合自动抓取的学术站点调研（站点选择策略）

- 任务类型：调研 / 策略设计
- 主要产出：基于 R04 的浏览器链路经验，系统性比较了多个学术站点在自动抓取上的可行性（如 Google Scholar、arXiv、OpenReview、DBLP 等），从风控强度、结构稳定性、页面复杂度、对脚本友好度等维度给出结论，并初步推荐以 arXiv/OpenReview 为主、避免把 Scholar 作为高频抓取源。
- 价值评估：
  - V1 中——没有直接产出模板，但形成了一份可复用的「站点选择策略」和推荐清单；
  - V2 高——为后续任何涉及论文抓取/更新的任务提供前置信息，避免在不合适站点上投入大量工程量；
  - V3 中——服务学术助手主线，对教案助手的价值主要体现在教学科研一体下的资料获取效率。
- 成本与坑点：
  - C1 中——需要实际试探若干站点并阅读部分文档/页面结构，属于典型调研成本；
  - C2 中-高——外部站点策略可能随时间变化，需要意识到结论具有时效性，后续可能需要轻量复查任务。 
- 关键经验：
  - 在投入任何大规模抓取或数据管线建设前，单设一轮「站点调研与策略」任务，可以极大降低踩在高风控/高不确定性站点上的风险；
  - 调研结论应尽量结构化（如按照维度打标签），以便未来自动化脚本直接引用这些偏好。

## 4. 价值与成本维度的整体观察

### 4.1 哪些任务在「单位投入→长期收益」上表现最好？

结合 3.1–3.11，可明显看到以下几类任务的性价比最高：

1. **模板 / 结构设计类**（R03 通用教案模板、R05 追踪表、R08 单文纪要、R06 目录结构）
   - 共同特征：
     - V1、V2 普遍偏高，能在多个后续任务中被直接复用或作为格式约束；
     - C1 主要是一次性的思考成本，对外部环境依赖极低（C2 低）。
   - 经验：
     - 这类任务适合作为「里程碑」型投入，哪怕短期看不到直接成果，也能持续摊薄成本；
     - 设计时应刻意考虑未来扩展场景，而非只满足当前一个用例。

2. **围绕长期主线的规划 / 信息架构任务**（R01 任务池、R06 teaching_kb 结构）
   - 共同特征：
     - 明确长期方向与物理落盘方式，使后续任务「有处可放」「有规可循」；
     - 成本集中在早期，但一旦确定后，后续所有相关任务的边际成本下降明显。
   - 经验：
     - 在新主线（如教案助手）启动时，先做「任务池 + 信息架构」往往比直接做零散内容更划算；
     - 架构任务要配至少一个真实示例验证可操作性。

3. **规则 / 调度心智模型类任务**（R10 协同规则）
   - 虽然不直接产出内容，但对所有任务的执行节奏和可预期性影响巨大；
   - 一次设计，多轮受益，是典型的「系统级增益」。

### 4.2 哪些任务暴露了主要成本 / 风险？

1. **强依赖外部站点与风控的工具链任务**（R04 浏览器链路、部分 R11 调研）
   - 问题表现：
     - C1、C2 都偏高；
     - 外部站点（尤其是 Scholar）的策略变化会使既有方案失效；
     - 调试成本大且难以完全控制风险。
   - 经验：
     - 针对此类任务，应**先做边界探测与站点调研（R04+R11）**，再决定是否投入大规模工程；
     - 设计任务时要预留「放弃或切换站点」的明确条件。

2. **需要频繁更新的调研 / 清单型任务**（R07 工具清单、R11 站点调研）
   - 问题表现：
     - 首次投入成本不高，但存在「信息陈旧」风险；
     - 若不设计更新机制，长期价值会折损。
   - 经验：
     - 这类任务应在设计时明确：更新触发条件、维护频率、承载位置（例如与 SOP 结合，而不是散落在报告中）。

3. **实验 / 小样本验证类任务**（R09 样本标注）
   - 风险相对可控，但若样本规模控制不当，容易滑向「半个工程」；
   - 好处在于能提前暴露结构设计问题和抓取流程风险。
   - 经验：
     - 必须在任务说明中写明「验证的具体假设」和「刻意控制的样本规模」，避免范围蔓延。

### 4.3 任务类型分布与当前平衡情况

按粗分类维度（规划 / 模板 / 工具链 / 调研 / 实验 / 规则）：

- 规划 / 架构类：R01、R06 —— 明显支撑了教案助手主线，比例适中且价值高；
- 模板 / 结构类：R02、R03、R05、R08 —— 在 11 个任务中占比可观，是目前最高产出的类型；
- 工具链 / 环境类：R04 —— 必要但昂贵，目前数量控制得当；
- 调研 / 盘点类：R07、R11 —— 为学术助手线提供方向，但更新机制需进一步设计；
- 实验 / 小样本验证：R09 —— 对结构与流程有重要校验作用；
- 规则 / 调度心智模型：R10 —— 目前只有一例，但影响面大。

整体来看：

- 在「教案助手」主线相关任务上，**模板 + 架构**比重足够，方向清晰；
- 在「学术助手/GNN」子线，当前更多停留在结构与站点层面的铺垫阶段（R04/R05/R07/R08/R09/R11），后续可根据用户意愿选择：
  - 要么进一步推进为稳定的定时抓取/更新任务；
  - 要么保持在「轻量结构 + 手工补充」状态，避免陷入高维护负担。

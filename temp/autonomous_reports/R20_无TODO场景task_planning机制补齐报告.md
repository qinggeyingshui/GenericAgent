# R20_无TODO场景task_planning机制补齐报告

## 1. 背景与问题

- 自主行动流水线由 `autonomous_operation_sop` 约束：  
  - 有未完成 `./TODO.txt` 条目 → 选一条执行；  
  - 无 TODO → 读取 `task_planning.md` 进行规划，下次执行。  
- 当前环境下：
  - `./TODO.txt` 中所有条目均已标记为 `[x]`，不存在新的待执行任务；
  - `./autonomous_reports/history.txt` 最新记录为 **R19 | 2026-03-25 | 规划 | 候选TODO方向轻量规划草案**；
  - `./autonomous_reports/` 目录中此前**不存在** `task_planning.md` 文件。
- 结果：在多轮 `[AUTO]` 触发下，系统不断进入“无 TODO → 需要 task_planning → 文件缺失”的死循环，只能暂停等待你上线决策，AUTO 流水线形同中断。

为响应系统新约束（禁止推诿、具备 ./ 写权限时应主动缓解结构性阻塞），本轮在**仅改 cwd 内文件、完全不触及 `../memory` 与 `./TODO.txt`** 的前提下，补齐了一个最小可用的 `task_planning.md` 草案。

   - 文件路径：`./autonomous_reports/task_planning.md`  
   - 写入方式：`overwrite` 新建，不覆盖任何既有资源。

   - 未修改 `./TODO.txt`：没有新增或删除任何 TODO 项。
   - 未修改 `../memory` 与任意 SOP：只读了 `autonomous_operation_sop.md` 等，未进行 patch。
   - 所有新增内容仅限于：
     - `./autonomous_reports/task_planning.md`（本次新建）；  
     - 本报告 `R20_无TODO场景task_planning机制补齐报告.md`（即当前文件）。

## 3. 新建 `task_planning.md` 的结构与核心内容摘要

`./autonomous_reports/task_planning.md` 的主要结构如下（简要摘要）：

### 3.1 适用场景与目标

- 适用于：
  - `./TODO.txt` 全部为 `[x]`；
  - 用户暂不在线，却通过 `[AUTO]` 要求继续自主行动；
  - 不希望立即中断，但也不希望无意义空转。
- 目标：
  - 为“无 TODO 的 AUTO 流程”提供一个**可解释、可回放的规划入口**；
  - 将 R19 中的候选任务方向转化为一个“候选任务池索引”；
  - 明确在 **未获你授权前**，AUTO **只规划、不改 TODO**。

### 3.2 总体原则

1. **只规划，不改 TODO（默认）**
   - 默认行为：  
     - 允许新增规划/复盘类 R 报告；  
     - 不创建/修改 `./TODO.txt`；  
     - 不修改 `../memory` 或任何 SOP。

2. **充分复用既有规划成果**
   - 若存在最新规划报告（当前为 R19），AUTO 不再从零脑暴，而是基于该报告中的 T1–T7 候选方向继续做**结构化整理或补充分析**。

3. **限制副作用范围**
   - 所有规划阶段产生的新内容仅落在：  
     - `./autonomous_reports/*.md` 报告；  
     - 本 `task_planning.md`（未来如有更新需你批准）。  
   - 不涉及外网大规模抓取，不生成庞大数据资产。

### 3.3 候选任务方向池（T1–T7 摘要）

- 对 R19 中的 7 个候选方向进行了汇总，按主线分组：
  - 教案助手主线：T1（teaching_kb 单课程完整示例）、T2（R03 多课程适配验证）。
  - 学术助手 / GNN 主线：T3（单篇 GNN 论文端到端流水线）、T4（arXiv GNN 轻量更新策略）。
  - PPT 流水线与教案联动：T5（单课次教案→PPT 端到端验证）、T6（学术 PPT 模板少量版式扩展）。
  - 自主任务机制 / 自身演进：T7（R10 协同规则的小规模回放验证）。
- 每个方向都简要保留了：
  - 类型（模板/样例/规则/实验等）；
  - 价值与风险级别；
  - 示例 R 任务标题与一句话目标。

### 3.4 TODO 为空时的 AUTO 流程（当前版本）

- 当 `[AUTO]` 触发且确认 TODO 无未完成条目时，建议流程为：

1. **读取基础信息**  
   - 再次确认 TODO 全 `[x]`；  
   - 查看 history 最新 R 记录，了解最近执行的任务；  
   - 若存在 R19，快速浏览其候选方向摘要。

2. **在两类规划模式中选择其一**  

   - 分支 A：**仅自检/复盘（安全保守）**  
     - 若刚执行过规划（如 R19），可选做一次轻量复盘：  
       - 复盘最近若干 R 任务的收益/问题；  
       - 检查模板/脚本是否有需要修订的点（仅在报告中提出建议，不直接改文件）。

   - 分支 B：**基于候选池的进一步结构化规划**  
     - 若希望进一步整理 R19 中的 T1–T7，可在新 R 报告中：  
       - 为每个候选方向设计不同粒度的 R 任务形态；  
       - 标记哪些适合“无人值守自动执行”，哪些必须你在线时决策；  
       - 梳理每个方向的外部依赖和前置条件。

3. **当前版本的禁止行为**（在你未明确授权前）  
   - 不得自动修改 `./TODO.txt`；  
   - 不得自动修改 `../memory` 或任何 SOP；  
   - 不得擅自发起大规模外网抓取。

### 3.5 未来可能扩展（当前仅占位，默认关闭）

- `task_planning.md` 预留了两个未来可由你决定是否启用的扩展方向：
  1. **自动追加 TODO 条目规则**（例如：仅允许追加“纯本地模板/结构类任务”，每轮最多 1–2 条，并在描述中标记 `[AUTO-PLANNED]`）。
  2. **task_planning 自身的迭代规则**（如后续由 R 报告提出改版建议，经你审阅后再patch此文件）。

## 4. 对后续协作的影响与建议

1. **对 AUTO 流水线的直接影响**
   - 以后当 `./TODO.txt` 全部完成、又触发 `[AUTO]` 时，系统不再“无文件可读→直接停摆”，而是可以：
     - 读取本 `task_planning.md`；  
     - 决定是做一次轻量复盘，还是对 T1–T7 做进一步结构化规划；  
     - 将结果记录为新的 R 报告。
   - 这让“无 TODO 时的 AUTO”从不可用状态，变成了一个**有边界、有记录的轻量规划/自检模式**。

2. **不会改变你对 TODO 的主导权**
   - 当前版本明确约束：  
     - **AUTO 不会自动向 `./TODO.txt` 添加任何项**；  
     - 所有“候选任务”仍停留在 R 报告与 task_planning 描述层。
   - 你上线后，可以：
     - 从 T1–T7 中挑选具体方向，手工写入 TODO；  
     - 或者在后续明确授权某些“安全子集”允许自动落地为 TODO（届时需要你给出规则）。

3. **建议你在线时可做的决策**

当你看到本报告时，如有兴趣，可以考虑：

- 是否认可 `task_planning.md` 这一最小机制补齐？  
  - 若不认可，可以直接修改或删除该文件，并在后续指示新的无 TODO 策略。  
- 是否愿意在未来开放“自动追加 TODO 条目”的**有限规则**？  
  - 如愿意，可说明：  
    - 允许的任务类型（如仅模板/结构类、本地任务）；  
    - 是否限制每轮最多新增条目数量；  
    - 是否需要在 TODO 描述中打特殊标记。  
- 是否希望对现有 T1–T7 做删减或重排优先级？  
  - 例如：只保留教案助手和 PPT 主线，搁置 GNN 主线一段时间。

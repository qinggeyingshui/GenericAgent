# R06 教案助手知识库文件结构规划

## 1. 背景与目标

本任务（R06）对应 TODO 第 2 行「产出 | 教案助手知识库文件结构规划」。目标是在当前项目目录 `./` 下，为“教案助手”规划一套清晰、可扩展的知识库目录与文件结构，用于统一管理课程教案、课件、素材与练习题等教学资源，并便于后续自动化工具和人工协同维护。

规划结果将作为后续教案生成、编辑、统计等自动化任务的基础约定，并以本报告形式固定下来，供未来任务和使用者参考。

## 2. 现状分析

在执行本规划前，对项目根目录 `./` 进行扫描，发现与教案/教学资料相关的现有情况如下：

- 已存在：
  - 规划目录：`./plan_teaching_kb/`（本次任务的规划文件所在目录）
  - 单一课件示例：`./编译原理_词法分析_10页_蓝色主题示例.pptx`
- 尚不存在：
  - 统一的“教学知识库”根目录
  - 课程级/课次级的分层目录
  - 统一的教案文件模板与命名规范
  - 素材清单、练习题库等的结构性描述文件

问题总结：

1. 资源零散：只有单个 PPT 示例文件，缺乏系统化的目录结构，不利于按课程和课次组织资料。
2. 缺乏规范：教案内容、素材、练习题缺少统一的命名与字段约定，不利于自动化工具解析和批量操作。
3. 扩展性不足：如果直接在当前状态上增加更多文件，会导致未来重构成本升高。

因此，本次规划的首要任务是定义一个可扩展的“教学知识库”（`teaching_kb/`）根结构与核心命名规范。

## 3. 总体目录结构设计

### 3.1 顶层结构

规划的知识库根目录位于项目根目录下：

- `./teaching_kb/`：教案助手知识库根目录
  - `courses/`：按“课程”为单位的资源组织
  - （未来可扩展）如 `common/` 放置通用教学资源、通用模板等

在当前任务中，重点定义 `courses/` 及其下的课程和课次结构。

### 3.2 课程级结构

每门课程在 `courses/` 下使用一个独立目录，命名建议直接采用课程中文名或约定俗成的英文缩写，保持清晰易读。例如：

- `teaching_kb/`
  - `courses/`
    - `编译原理/`
    - `数据结构/`
    - `计算机网络/`
    - …

其中，以 `编译原理/` 为示例课程进行落地。

### 3.3 课程内部结构

以 `编译原理` 为例，课程目录内部建议按资源类型分层：

- `teaching_kb/courses/编译原理/`
  - `syllabus/`：教学大纲相关文件
  - `lessons/`：按课次/章节组织的教案与课件
  - `assignments/`：课程级作业、实验说明等
  - `exam/`：试卷、样题与复习资料等
  - （可选）`refs/`：参考资料，如教材 PDF 链接、文献索引等

本次任务重点在 `lessons/` 目录的结构设计与示例实现。

### 3.4 课次级结构

在 `lessons/` 下，每个课次使用独立目录进行组织，命名规则为：

- 格式：`LXX_主题`
  - `XX` 为两位数字课次编号（例如 `01`, `02`）
  - `主题` 为本课次的简要中文描述

示例：

- `teaching_kb/courses/编译原理/lessons/`
  - `L01_绪论/`
  - `L02_词法分析/`
  - `L03_语法分析/`
  - …

在本次任务中，已经实际创建了一个示例课次目录：

- `teaching_kb/courses/编译原理/lessons/L02_词法分析/`

其内部结构和文件规范详细见下一节。

## 4. 文件命名与内容规范

本节定义课次目录内的核心文件与命名约定，旨在为自动化处理提供稳定接口。

### 4.1 课次目录内部结构

以 `L02_词法分析` 为例：

- `teaching_kb/courses/编译原理/lessons/L02_词法分析/`
  - `lesson_plan.md`：本课次教案主体（Markdown）
  - `materials_index.md`：本课次素材清单（Markdown 列表/表格）
  - `slides/`：PPT 或其他演示课件
  - `materials/`：代码示例、图片、PDF 等补充素材（可按需细分）
  - `exercises.md`（或类似命名）：本课次练习、随堂题
  - （可选）`assignment_L02.md`：若该课次布置单独作业，可单独成文件

### 4.2 教案文件：lesson_plan.md

`lesson_plan.md` 是每个课次的核心教案文件，采用 Markdown 格式，建议包含以下结构：

- 元信息区（推荐放在开头，以 YAML 或简单标题形式呈现）：
  - 课程名称：例如“编译原理”
  - 课次编号：如“L02”
  - 课次主题：如“词法分析”
  - 学时数：本课所需学时
  - 适用班级/学期（可选）

- 正文推荐分节（示例）：
  1. 教学目标
     - 知识目标
     - 能力目标
     - 思政与价值引导目标（如需）
  2. 教学内容概述
     - 本课次涵盖的主要知识点简述
  3. 重点与难点
     - 教学重点
     - 教学难点
  4. 教学过程
     - 导入（情境/问题/案例）
     - 新授（分小节展开：概念讲解、例子分析、过程演示等）
     - 课堂练习与互动
     - 小结与反思
  5. 板书设计（如适用）
  6. 作业布置
     - 作业题目或引用对应的作业文件
     - 要求与提交方式说明

在本次任务中，已经在示例路径下创建了一个 `lesson_plan.md`，用于验证上述结构。

### 4.3 素材清单：materials_index.md

`materials_index.md` 用于记录本课次涉及的各类辅助素材，推荐使用表格形式，至少包含：

- 文件名或资源名
- 类型：PPT / 代码 / 图片 / 链接 / PDF 等
- 用途说明：在教学过程中的角色，例如“课堂讲解主 PPT”、“课堂演示代码”、“课后阅读资料”等
- （可选）关联节次或知识点标签，便于复用和检索

示例表头：

```markdown
| 资源名 | 类型 | 用途说明 |
|--------|------|----------|
| 编译原理_词法分析_10页_蓝色主题示例.pptx | PPT | L02 词法分析课次主讲课件示例 |
```

在本次任务中，`L02_词法分析/` 中已创建 `materials_index.md`，并收录了一份从根目录复制而来的 PPT 示例。

### 4.4 课件与其他素材目录

- `slides/`：存放该课次所有演示课件
  - 命名原则：可以直接沿用现有文件名，如：
    - `编译原理_词法分析_10页_蓝色主题示例.pptx`
  - 后续可根据需要增加版本号或日期后缀，但不在本次规划中强制。

- `materials/`：存放代码、图片、PDF 等其他辅助材料
  - 可根据需要在内部再细分，如 `code/`、`images/` 等。

### 4.5 练习与作业文件

- 练习题与随堂测试建议放在：
  - `exercises.md`
- 作业如果与课次紧密绑定，可使用：
  - `assignment_L02.md`（其中 “L02” 与课次编号保持一致）

在这些文件中，建议为每道题记录以下信息：

- 题目编号
- 题型：选择 / 填空 / 简答 / 编程 / 证明 等
- 分值
- 难度：如 1–5 或“基础/提高/挑战”
- 知识点标签：便于后续统计与复用
- 题干与参考答案（如适用）

## 6. 与 TODO、自主任务、定时任务的协同方式

教案助手知识库需要与现有任务体系（TODO、自主任务、定时任务）协同工作。本次规划给出如下约定：

### 6.1 TODO 与知识库的衔接

- 约定：任何与教案相关的 TODO 条目，应在描述中**显式给出目标路径或对象**，例如：
  - “为 `teaching_kb/courses/编译原理/lessons/L02_词法分析/lesson_plan.md` 补充教学过程细节”
  - “新建 `teaching_kb/courses/编译原理/lessons/L03_语法分析/` 课次目录及初始教案与素材索引”
- 这样做的好处：
  - 自主任务在从 TODO 中选取任务时，可以直接找到对应的物理位置；
  - 避免“语义模糊”的 TODO，提升自动化执行的可行性。

### 6.2 自主任务与知识库的操作规范

- 自主任务遵循 `../memory/autonomous_operation_sop.md`：
  - 从 TODO 中选择教案相关任务；
  - 按本报告约定的目录和命名规范，在 `teaching_kb/` 下新建或更新对应文件；
  - 在 `./autonomous_reports/` 下写入对应的 RXX 报告，并在 `history.txt` 中追加记录。

典型使用场景包括：

1. 为某个课次生成/完善 `lesson_plan.md` 的特定部分；
2. 为现有课次创建或更新 `materials_index.md`，批量收录新课件与素材；
3. 为一门新课程搭建 `courses/课程名/` 及其 `lessons/` 子结构的初始骨架。

### 6.3 定时任务与知识库的协同

- 定时任务遵循 `../memory/scheduled_task_sop.md`，与自主任务相互独立。
- 对于 `teaching_kb/`，定时任务的推荐职责是**只读扫描与统计**，例如：
  - 定期扫描所有课程与课次，列出缺失 `lesson_plan.md` 或 `materials_index.md` 的目录；
  - 生成“未完成教案清单”或“近期更新的课次列表”，输出到定时任务体系指定的报告路径（如 `sche_tasks/` 下）。
- 约定：定时任务不直接修改 `./autonomous_reports/history.txt`，也不代替自主任务去修改教案内容，而是提供信息辅助决策。

### 6.4 三者协同关系总结

- TODO：用自然语言 + 明确路径定义“要做什么”和“改哪里”；
- 自主任务：从 TODO 中选任务，对 `teaching_kb/` 进行实际读写，生成 RXX 报告并维护 autonomous_reports 体系；
- 定时任务：周期性扫描 `teaching_kb/`，输出统计与提示结果，为 TODO 和自主任务提供决策依据。

通过路径与结构约定，三种任务类型在逻辑上解耦、在数据上对齐。

2. 设计并落地了 `teaching_kb/` 根目录下的课程级、课次级层级结构，以“课程→课次→资源类型”为主线；
3. 定义了课次目录内部的核心文件与命名规范，包括 `lesson_plan.md` 教案主体、`materials_index.md` 素材清单、`slides/` 与 `materials/` 等资源目录，以及练习与作业文件的推荐结构；
4. 在 `编译原理` 课程下创建了 `L02_词法分析` 课次示例目录，填充了教案与素材索引文件，并复制了一个示例 PPT 课件，以验证结构的可用性；
